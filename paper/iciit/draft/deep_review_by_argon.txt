# HIGH LEVEL SUMMARY
---
## Summary
This paper introduces the Tabular Transformation Discovery Harness, an autonomous two-tier evaluation framework designed to benchmark Large Language Model (LLM) agents on inverse tabular program induction. Given observational dataset pairs before and after transformation ($\mathcal{D}_{\text{before}}, \mathcal{D}_{\text{after}}$), agents must infer and synthesize the exact latent Python transformation pipeline across six structural complexity classes (ranging from atomic unary operations to deep hybrid Abstract Syntax Trees) and eight real-world domains ($N = 48$ tasks). The harness enforces strict epistemic isolation by decoupling an interactive, budget-constrained Read-Eval-Print Loop (REPL) discovery sandbox on training splits (Tier 1) from an isolated black-box container evaluation on hidden holdout distributions alongside white-box symbolic AST verification (Tier 2). Through cross-paradigm comparisons and a three-mode ablation study, the authors demonstrate that interactive execution feedback is indispensable for inverse tabular reasoning and that while programmatic compilation from known operator vocabularies is highly reliable in frontier models, open-ended hypothesis search and budget-aware stopping heuristics remain the primary operational bottlenecks.

## Strengths
* **Novel Problem Formalization and Two-Tier Epistemic Isolation:** The work addresses the practically important problem of unguided, multi-column inverse tabular program induction—incorporating stateful distribution scalers, piecewise conditional logic, and branching cross-column interactions—within a rigorous two-tier sandbox architecture that prevents test-set distribution leakage and cleanly separates exploratory discovery from out-of-sample generalization.
* **Insightful Diagnostic Metrics and Three-Mode Ablation Protocol:** By pairing decoupled Conditional Accuracy ($\text{Acc}_{\text{cond}}$) and Penalized Accuracy ($\text{Acc}_{\text{pen}}$) metrics with a three-mode ablation protocol (direct zero-shot generation, full interactive REPL search, and revealed oracle operator synthesis), the benchmark effectively disentangles mathematical hypothesis discovery and stopping policies from syntactic code compilation.
* **Actionable Empirical Findings on Agentic Behavior:** The empirical analysis surfaces clear behavioral trade-offs across model families, showing that frontier models fail without execution feedback ($3.6\%$ conditional accuracy), achieve $100\%$ conditional recovery when oracle operators are disclosed, and diverge sharply in risk-aware stopping behavior under hard resource budgets.

## Weaknesses
* **Discrepancy Between Claimed Model Names and Evaluated API Snapshots:** Throughout the prose and tables, the paper reports evaluating "Gemini 3 Flash" and "GPT-5.4 Nano" (characterized as a lightweight edge reasoning model), whereas Section 4.2 explicitly specifies that the executed API snapshots were `gemini-2.0-flash-exp` and `gpt-4o-mini-2024-07-18`; the authors should align the model nomenclature with the actual checkpoints evaluated or re-run the experiments on authentic snapshots of the claimed model families.
* **Flawed Implementation of the Custom Symbolic Baseline and Omission of Established Non-LLM Comparators:** The custom depth-3 Symbolic Enumeration baseline omits stateful parameter persistence for training-split moments ($\mu, \sigma, x_{\min}, x_{\max}$) and in-place column matching priorities—artificially degrading its accuracy on elementary Class 0 and Class 1 tasks—and the empirical evaluation excludes established symbolic regression and pipeline synthesis frameworks that avoid brute-force combinatorial explosion (Reference Paper: Interpretable Machine Learning for Science with PySR and SymbolicRegression.jl, Miles Cranmer, 2023; Reference Paper: AI Feynman: A physics-inspired method for symbolic regression, Silviu-Marian Udrescu and Max Tegmark, 2020; Reference Paper: LLM-SR: Scientific Equation Discovery via Programming with Large Language Models, Parshin Shojaee et al., 2025; Reference Paper: Auto-Pipeline: Synthesizing Complex Data Pipelines By-Target Using Reinforcement Learning and Search, Junwen Yang et al., 2021).
* **Arithmetic Inconsistency Between the Ablation Subset and Domain Breakdown Tables:** Under deterministic greedy decoding ($\text{seed}=42$), the standard full-agent results for Gemini 3 Flash on the 24-task ablation subset in Table 2 ($13/24$ submissions, $0.923$ conditional accuracy, $0.500$ penalized accuracy) conflict mathematically with the sum of the exact same four domains in Table 3 ($12/24$ submissions, $0.868$ conditional accuracy, $0.434$ penalized accuracy), which the authors should reconcile or clarify.
* **Under-Specification of Stateful Scaler Conventions, Piecewise Operators, and White-Box AST Verification:** Several methodological details required for independent reproducibility—including whether `StandardScaler` uses sample ($\text{ddof}=1$) or population ($\text{ddof}=0$) standard deviation under the strict $\epsilon = 10^{-4}$ tolerance, how free thresholds $\theta$ and guarded domains are parameterized for $\Omega_5$ operators, and how the `ast` parser resolves expanded scalar arithmetic and branching DAG topological orderings—would benefit from formal clarification.
* **Confounded Multimodal Tool Access, Unreported Resource Telemetry, and Small Sample Size per Stratum:** Restricting `read_image` access to Claude and Gemini while withholding it from vision-capable `gpt-4o-mini`, omitting empirical token and tool-call exhaustion breakdowns, and evaluating only a single task seed per dataset-class cell ($N = 48$ total tasks across a closed 24-operator vocabulary) limit the statistical granularity and causal attribution of the cross-model comparisons.

## Potential Issues And Suggestions
### [Introduction, Problem Motivation, and Related Work] (Pages: 1-3)
#### Potential Mistakes and Improvements

1. **Positioning of Symbolic Regression Literature vs. Multi-Column DAG Recovery and the Chosen Baseline (Potential Concern):**
   In Section 2.2 (*Program Synthesis, Table Wrangling, and Symbolic Regression*, page 2), the paper notes that modern symbolic regression frameworks—specifically citing **PySR** [6], **AI Feynman** [28], and **LLM-SR** [24]—utilize evolutionary search, physics-inspired modular decomposition, or LLM-guided program search specifically *"to avoid exhaustive combinatorial enumeration."* It then distinguishes the proposed benchmark by arguing that existing symbolic regression benchmarks evaluate *"single-target functional recovery on isolated numerical vectors, rather than discovering multi-stage, branching tabular DAG transformations over heterogeneous multi-column datasets."* This framing raises two closely related concerns:
   * **Decomposability to Column-Wise Multivariate Recovery:** Under the problem formulation in Section 3, each modified column $c \in \mathcal{C}_{\text{trans}}$ in $\mathcal{D}_{\text{after}}$ is an observed output column generated by a depth-1 to depth-3 composition of columns in $\mathcal{D}_{\text{before}}$. Because intermediate states do not cross beyond the depth-3 expression tree of each target column relative to $\mathcal{D}_{\text{before}}$, recovering the transformation for a table with $|\mathcal{C}_{\text{trans}}|$ modified columns decomposes into $|\mathcal{C}_{\text{trans}}|$ independent single-target multivariate symbolic regression sub-problems over the input feature matrix $\mathcal{D}_{\text{before}}$ (which is how the paper's own symbolic baseline operates via column-wise $L_1$ residual minimization). Framing the task in Section 2.2 as fundamentally irreducible to single-target multivariate functional recovery slightly overstates the structural gap; clarifying that the distinction lies primarily in identifying *which* columns were modified, preserving *stateful train-to-test distribution scalers* ($\Omega_3$), and estimating *piecewise conditional thresholds* ($\Omega_5$) would make this positioning more precise.
   * **Exclusion of Non-Brute-Force Symbolic Baselines:** Despite noting in Section 2.2 that established symbolic regression solvers (PySR, AI Feynman, LLM-SR) are designed to avoid brute-force combinatorial explosion, the cross-paradigm study introduced in the Abstract and Section 1 (Contribution 4) compares the LLM agents solely against a naive depth-3 combinatorial brute-force enumeration baseline that predictably collapses on Class 5 ($\mathcal{O}(M^d \cdot |\Omega|^d)$). Clarifying in Sections 1 and 2.2 why column-wise application of established symbolic regression frameworks was excluded—or explicitly framing the symbolic comparator in Section 1 as a naive brute-force reference rather than a representative symbolic regression baseline—would strengthen the fairness of the cross-paradigm comparison.

2. **Inaccurate Description of "Monotonic Degradation" in the Abstract (Definitive Inconsistency):**
   The Abstract (page 1) states that *"GPT-5.4 Nano achieves 100% submission but suffers a steep monotonic degradation from 1.000 on Class 0 to 0.250 on Class 5."* According to Table 1 (page 7) and Section 5.1.1 (page 6), the penalized transformed accuracy of this model across Classes 0 through 5 is $1.000, 0.875, 0.333, 0.312, 0.375,$ and $0.250$. Because accuracy increases on Class 4 ($0.375$) relative to Class 2 ($0.333$) and Class 3 ($0.312$), the degradation across the six complexity classes is not strictly monotonic. Replacing *"monotonic degradation"* with *"substantial degradation"* (or noting the rebound on Class 4) would ensure consistency with the empirical tables.

3. **Ambiguity in Ablation Metric Naming in the Abstract (Potential Concern):**
   When summarizing the three-mode ablation study, the Abstract (page 1) states that *"direct symbolic generation without execution feedback fails almost entirely (3.6% accuracy), whereas revealing oracle operator vocabularies yields perfect 100% conditional functional recovery on submitted tasks (66.7% penalized accuracy)."* Referring to Table 2 (page 7), $3.6\%$ ($0.036$) is specifically the *conditional transformed column accuracy* (`Trans. (Cond)`), whereas its *penalized transformed accuracy* (`Trans. (Pen)`) is $2.1\%$ ($0.021$) and its *conditional functional accuracy* (`Func. (Cond)`) is $63.9\%$ ($0.639$). Explicitly specifying that $3.6\%$ refers to *conditional transformed accuracy* (and $2.1\%$ penalized) would prevent confusion when contrasted directly against the *"conditional functional recovery"* and *"penalized accuracy"* terminology in the second half of the sentence.

#### Minor Corrections and Typos

* **Page 3, Section 2.3:** In the citation *"FeatEng [20]"*, the corresponding reference entry [20] (*"Can Models Help Us Create Better Models? Evaluating LLMs as Data Scientists"*) does not contain the name "FeatEng" in its title; briefly introducing or aligning the benchmark name with the cited paper's title on first mention would aid reader clarity.

### [Problem Formulation, Harness Architecture, and Evaluation Metrics] (Pages: 3-5)
#### Potential Mistakes and Improvements

1. **Stateful Scaler Parameterization, Hardcoded Constants, and Degrees of Freedom ($\Omega_3$, Section 3.1 & Section 3.4.1):**
   In Section 3.1 ("Parameterization of Stateful Scalers"), the text specifies that for stateful distribution-level operators in $\Omega_3$ (`StandardScaler` and `MinMaxScaler`), empirical moments ($\mu, \sigma, x_{\min}, x_{\max}$) are fitted strictly on $\mathcal{D}_{\text{train\_before}}$, and that in Tier 2 evaluation, the synthesized `transform(df)` script applies these frozen scalar constants directly to $\mathcal{D}_{\text{test\_before}}$. This introduces two potential concerns regarding reproducibility and functional evaluation validity:
   - *Frozen Constants vs. Dynamic Computation in `transform(df)`:* Because Tier 2 executes `transform(df)` in an isolated container where only $\mathcal{D}_{\text{test\_before}}$ is mounted and $\mathcal{D}_{\text{train\_before}}$ is absent (Figure 1 and Section 3.3.3), the submitted standalone function `transform(df)` receives only the test DataFrame argument `df`. If an agent writes standard idiomatic pandas or scikit-learn code inside `transform(df)`—such as `(df[c] - df[c].mean()) / df[c].std()` or `StandardScaler().fit_transform(df[[c]])`—it will match $\mathcal{D}_{\text{train\_after}}$ with zero residual error during Tier 1 checks on $\mathcal{D}_{\text{train\_before}}$, but will compute test-set moments ($\mu_{\text{test}}, \sigma_{\text{test}}$) during Tier 2 evaluation. Because finite-sample moments on the 30% test split differ from the 70% training split by more than the strict numerical tolerance $\epsilon = 10^{-4}$ (Eq. 7), such a script would fail Tier 2 functional verification despite identifying the exact operator. Similarly, `IndicatorMean` ($\mathbf{1}_{\{x > \mu\}} \in \Omega_5$) depends on the empirical mean $\mu$, and it is not stated whether $\mu$ in $\Omega_5$ is also treated as a frozen training parameter. Clarifying whether the system prompt explicitly instructs agents to hardcode fitted training-set moments as floating-point literals inside `transform(df)` is necessary to understand the evaluation protocol.
   - *Standard Deviation Degrees of Freedom ($\text{ddof}$):* Section 3.1 defines `StandardScaler` as $(x - \mu)/\sigma$ without specifying whether $\sigma$ uses the unbiased sample standard deviation ($\text{ddof}=1$, the default in `pandas.Series.std()`) or the population standard deviation ($\text{ddof}=0$, the default in `numpy.std()` and `sklearn.preprocessing.StandardScaler`). Because the relative difference between $\text{ddof}=0$ and $\text{ddof}=1$ scales as $\approx \frac{1}{2 N_{\text{train}}}$, on smaller datasets in the benchmark (e.g., $N_{\text{train}} = 398$ or $537$), the relative discrepancy is $\approx 1.26 \times 10^{-3}$ and $\approx 9.3 \times 10^{-4}$ respectively—exceeding the $\epsilon = 10^{-4}$ tolerance in Eq. (7) by an order of magnitude and potentially causing valid implementations to fail functional evaluation solely due to library default conventions.

2. **Inconsistency and Under-Specification in Piecewise/Conditional Operators ($\Omega_5$, Section 3.1 & Eq. 3, Section 3.2):**
   There is a potential methodological and reproducibility gap between the discrete operator library $\Omega_5$ defined in Section 3.1 (Page 3) and the formalization of Class 4 (Piecewise / Conditional Logic) in Section 3.2 (Page 4):
   - *Mismatch Between $\Omega_5$ and Equation (3):* Section 3.2 defines Class 4 as consisting of *"3 independent columns prioritized with conditional/piecewise unary operators from $\Omega_5$, plus 1 conditional cross-column interaction $z = \mathbf{1}_{\{x_j > \theta\}} \cdot x_i$, requiring numerical threshold estimation,"* followed by Equation (3) defining a general univariate two-branch function $y = f_1(x)$ if $x > \theta$ else $f_2(x)$. However, among the five operators listed in $\Omega_5$ in Section 3.1—`IndicatorZero` ($\mathbf{1}_{\{x>0\}}$), `IndicatorMean` ($\mathbf{1}_{\{x>\mu\}}$), `ClipZero` ($\max(0, x)$), `PiecewiseLog` ($\mathbf{1}_{\{x>0\}} \ln x$), and `ConditionalInteraction` ($\mathbf{1}_{\{x_j>\theta\}} \cdot x_i$)—all four unary operators have fixed thresholds ($0$ or $\mu$) and fix the false branch to $0$. Only the bivariate `ConditionalInteraction` contains a free threshold parameter $\theta$ (and is bivariate rather than univariate as in Eq. 3). Furthermore, Section 3 does not specify whether unary operators in Class 4 can take arbitrary thresholds $\theta$ and non-zero fallback branches $f_2(x)$, nor how ground-truth thresholds $\theta$ are sampled or parameterized during task construction (e.g., whether $\theta$ is drawn from specific empirical quantiles of $\mathcal{D}_{\text{train\_before}}$ and frozen for Tier 2).
   - *Vectorized Evaluation and Precondition Domain of `PiecewiseLog`:* In Section 3.1, `PiecewiseLog` is written algebraically as $(\mathbf{1}_{\{x>0\}} \ln x)$. In standard IEEE-754 floating-point array execution (`numpy`/`pandas`), evaluating the product `(x > 0) * np.log(x)` or an unguarded `np.where(x > 0, np.log(x), 0)` on columns containing $x \le 0$ evaluates $\ln(x)$ prior to masking, yielding `0 * (-inf) = NaN` (at $x=0$) or `NaN` (for $x<0$), which results in $m(c) = 0$ under Section 3.4.1. Conversely, if precondition sampling enforces $x > 0$ across the entire column, then $\mathbf{1}_{\{x>0\}} \equiv 1$ everywhere and `PiecewiseLog` reduces to standard `Log` ($\Omega_1$). Clarifying that `PiecewiseLog` is defined via guarded conditional evaluation (e.g., `np.where(x > 0, np.log(np.maximum(x, eps)), 0.0)`) and specifying its column eligibility rule (such as requiring columns that straddle $0$) would prevent ambiguity.

3. **Ambiguity in White-Box Symbolic AST Verification, Canonicalization, and Topological Ordering (Sections 3.3.1, 3.4.3, and 6.2):**
   In Section 3.4.3 (Page 5), the harness parses the submitted script into an AST via Python's `ast` module *"to extract the executed operator sequence $\widehat{\mathcal{O}}_{\text{AST}}$, verifying consistency against the agent's declared $\widehat{\mathcal{O}}$ in `submit_solution`,"* before computing Operator F1 ($\text{F1}_{\text{op}}$, Eq. 10) and Exact Sequence Accuracy ($\text{Acc}_{\text{seq}}$, Eq. 11). Several aspects of this evaluation protocol are underspecified for independent reproduction:
   - *Resolution of Discrepancies Between $\widehat{\mathcal{O}}_{\text{AST}}$ and $\widehat{\mathcal{O}}$:* Equations (10) and (11) are written solely in terms of $\widehat{\mathcal{O}}$ and $\widehat{\mathcal{O}}_c$ rather than $\widehat{\mathcal{O}}_{\text{AST}}$. It is unclear which representation is authoritative if the static AST extraction $\widehat{\mathcal{O}}_{\text{AST}}$ disagrees with the agent's self-reported $\widehat{\mathcal{O}}$, whether a mismatch incurs a penalty, and how the table-level operator list $\widehat{\mathcal{O}}$ passed to `submit_solution(script, \widehat{\mathcal{O}})` is partitioned into per-column sequences $\widehat{\mathcal{O}}_c$ in Eq. (11).
   - *Tension Between Inline Scalar Arithmetic, Algebraic Equivalence, and AST Token Matching:* When an agent implements `StandardScaler` or `MinMaxScaler` using frozen scalar constants as required by Section 3.1 (e.g., `(df[c] - 4.21) / 1.83`), or writes `Sigmoid` using primitive arithmetic (`1 / (1 + np.exp(-df[c]))`), the Python AST contains binary subtraction and division nodes (`Subtract`, `Divide` $\in \Omega_4$) rather than named scaler or activation calls. How canonical AST normalization maps expanded scalar arithmetic back to canonical operators in $\Omega_2$ or $\Omega_3$ without conflating them with $\Omega_4$ is not explained. Furthermore, while Section 3.4.3 notes that syntactic AST comparisons cannot recognize higher-order algebraic equivalences (e.g., $x \cdot x \equiv x^2$, commutativity $x_i + x_j \equiv x_j + x_i$, or affine reparameterizations of scalers), Section 6.2 does not discuss that this syntactic rigidity may systematically underestimate true structural recovery in Tables 1 and 2 when models synthesize algebraically equivalent code, or note computer algebra equivalence checking (e.g., via SymPy) as a direction for improvement.
   - *Topological Ordering of Branching DAGs in Eq. (11):* Equation (11) defines $\text{Acc}_{\text{seq}}$ by checking whether $\widehat{\mathcal{O}}_c = \mathcal{O}_c^*$ in *"identical topological order."* While linear unary compositions (Classes 0–2) have a unique topological order, columns in Classes 3–5 form branching trees/DAGs (e.g., $y = f(g(x_i) \star h(x_j))$) that admit multiple valid topological sortings depending on branch traversal order. How branching column ASTs are linearized into a unique canonical sequence $\mathcal{O}_c^*$—and whether ordered operand column bindings $(x_i, x_j)$ are also verified for non-commutative operators (`Subtract`, `Divide`, `ConditionalInteraction`)—should be formally specified.
   - *Zero-Division Guard in Precision (Eq. 10):* In Eq. (10), $\text{Precision} = \frac{|\widehat{\mathcal{O}} \cap \mathcal{O}^*|}{|\widehat{\mathcal{O}}|}$ is undefined if a submitted script contains no recognized canonical operators ($|\widehat{\mathcal{O}}| = 0$). Explicitly noting that $\text{Precision} = 0$ when $|\widehat{\mathcal{O}}| = 0$ and clarifying that $|\widehat{\mathcal{O}} \cap \mathcal{O}^*|$ denotes multiset intersection cardinality would make Eq. (10) mathematically complete.

4. **Under-Specification of DAG Depth ($d$), Execution Order, Precondition Sampling, and Schema Replacement Rules Across Complexity Classes (Sections 3.1, 3.2, 4.1, and 5.3.3):**
   In Sections 3.1, 3.2 (Pages 3–4), 4.1 (Page 5), and 5.3.3 (Page 7), the structural complexity classes, precondition rejection sampling, and column schema mappings leave several structural rules ambiguous:
   - *AST Depth and Input Sources in Classes 3–5:* While Classes 0–2 explicitly specify both $|\mathcal{C}_{\text{trans}}|$ and depth $d$, Class 3 specifies *"3 independent composed unary transformations plus 1 bivariate cross-column interaction $z = x_i \star x_j$"* without stating the depth $d$ of the composed unary transformations (presumably $d=2$) or whether $x_i, x_j$ in Classes 3 and 4 are strictly raw untransformed columns from $\mathcal{D}_{\text{before}}$ or can reference already-transformed unary columns. Similarly, Class 4 does not state the depth $d$ of its unary transformations, and Class 5 bounds the number of transformed columns by an inequality (*"Up to $|\mathcal{C}_{\text{trans}}| \le 6$ columns... up to depth $d=3$"*) while illustrating depth $d=3$ with $y = f(x_i \star x_j)$ (which has AST depth 2: a binary operator followed by one unary operator).
   - *Column Replacement vs. Appending and Parallel vs. Sequential Semantics on Low-Dimensional Tables:* Section 3.1 states that newly synthesized columns from cross-column interactions or piecewise splits are assigned *"anonymized standard identifiers (e.g., target feature replacements or indexed identifiers),"* and Section 4.1 states that *"in-place transformed columns retain their exact schema identifiers in $\mathcal{C}_{\text{after}}$, while interaction features in Classes 3–5 replace designated schema targets or adopt neutral indices."* Overwriting an existing column in-place preserves the column count ($P = M$) and reuses an original schema identifier, whereas assigning a new indexed identifier increases the column count ($P > M$). In a 4-column dataset like `banknote_authentication` ($M = 4$) or a 6-column dataset like `airfoil_self_noise` ($M = 6$), if 3 columns undergo in-place unary transformations in Classes 3–4 and the 4th column is replaced in-place by a bivariate interaction $z = x_i \star x_j$, the source columns $x_i, x_j$ must overlap with columns being modified in-place (unless $P > M$). Furthermore, because Class 5 is defined as an inequality ($|\mathcal{C}_{\text{trans}}| \le 6$), the exact deterministic rule for choosing $|\mathcal{C}_{\text{trans}}|$ (the denominator of $\text{Acc}_{\text{trans}}$ in Eq. 8) and whether all transformations in $\mathcal{T}(\mathcal{D}_{\text{before}})$ read strictly in parallel from the unmodified input snapshot $\mathcal{D}_{\text{before}}$ or execute sequentially in-place should be formalized.
   - *Precondition Rejection Sampling on Zero-Centered Datasets:* Section 5.3.3 notes that `banknote_authentication` features exhibit *"zero-centered bimodal distributions."* Under strict precondition rejection sampling (Section 4.1)—where raw column values must strictly satisfy domain constraints ($x > 0$ for `Log`/`PiecewiseLog`, $x \ge 0$ for `SquareRoot`) without shifting or clipping—a substantial fraction of unary operators in $\Omega_1$ and $\Omega_5$ is ineligible for zero-centered columns. Documenting the eligible operator pool per dataset would improve reproducibility.

5. **Stratified Splitting Criterion on Continuous Datasets, Budget Telemetry Visibility, and Tier 1 File Protection (Sections 3.1, 3.3.1, and 3.3.2):**
   - *Stratification on Continuous Tables (Section 3.1):* Section 3.1 states that the raw dataset is split into $\mathcal{D}_{\text{train}}$ (70%) and $\mathcal{D}_{\text{test}}$ (30%) *"using stratified deterministic pseudo-random permutation (seed = 42)."* Because all columns in $\mathcal{D}_{\text{before}} \in \mathbb{R}^{N \times M}$ are treated as a continuous feature space without a designated categorical label—and several benchmarked datasets (Section 4.1) are continuous regression tables—the text should clarify which column or quantile-binning scheme defines the strata (or whether standard unstratified shuffling is used when no discrete target exists).
   - *Visibility of Budget Telemetry (Section 3.3.2):* Section 3.3.2 defines hard episode limits on tool invocations $T_{\text{calls}}(c)$, cumulative tokens $K_{\text{tokens}}(c)$, and wall-clock time $\Delta t_{\text{wall}}(c)$ (Eqs. 4–6), and Section 3.4.2 penalizes episodes that exhaust their budget without calling `submit_solution` with a score of $0$. Because agent stopping behavior under budget constraints is a central aspect of the evaluation, Section 3.3 should clarify whether the agent receives real-time budget telemetry during the episode (e.g., remaining tool calls, token usage, or elapsed time injected into REPL feedback, or a final warning prompt before termination) or whether the budget ceilings are unobservable to the agent.
   - *Tier 1 Training Data Protection (Section 3.3.1):* While Section 3.3.3 explicitly states that $\mathcal{D}_{\text{test\_before}}$ is mounted read-only in Tier 2, Section 3.3.1 notes that persistent artifacts across `run_python` calls in Tier 1 are maintained via disk files. Clarifying whether $\mathcal{D}_{\text{train\_before}}$ and $\mathcal{D}_{\text{train\_after}}$ are also mounted read-only (or restored between calls) in Tier 1 would confirm that an exploratory script cannot inadvertently overwrite the source training files on disk mid-episode.

### [Experimental Setup, Empirical Results, and Ablation Analysis] (Pages: 5-8)
#### Potential Mistakes and Improvements

1. **Numerical Inconsistency Between the 24-Task Ablation Subset (Table 2) and Domain-Level Breakdown (Table 3) for Gemini 3 Flash:**
   There is a definitive arithmetic discrepancy between the ablation study results reported in Table 2 (page 7) and the domain-specific evaluation reported in Table 3 (page 8) for the identical model (`Gemini 3 Flash`) under the standard full-agent configuration:
   - **Submission Counts:** Section 4.2 (page 5) specifies that all LLM evaluations use deterministic greedy decoding ($T = 0.0$, $\text{top-}p = 1.0$, fixed $\text{seed} = 42$). Section 4.3 (page 5) states that the ablation study evaluates Gemini 3 Flash across a balanced stratified subset of $N = 24$ tasks spanning four specific domains (`concrete_strength`, `wine_quality`, `california_housing`, and `banknote_authentication` $\times$ 6 complexity classes). Under the *Standard Interactive Discovery (Full Agent)* condition—which represents the standard two-tier harness used in the main evaluation—Table 2 reports **13/24 (54.2%)** submissions. However, summing Gemini 3 Flash's submitted tasks (`Sub.`) across those exact four domains in Table 3 yields $4/6\ (\text{concrete\_strength}) + 2/6\ (\text{wine\_quality}) + 3/6\ (\text{california\_housing}) + 3/6\ (\text{banknote\_authentication}) = \mathbf{12/24\ (50.0\%)}$, rather than $13/24\ (54.2\%)$.
   - **Conditional and Penalized Accuracy Scores:** In Table 2, the *Standard Interactive Discovery (Full Agent)* row reports a Conditional Transformed Accuracy (`Trans. (Cond)`) of **0.923** and a Penalized Transformed Accuracy (`Trans. (Pen)`) of **0.500** (implying a sum of task accuracy scores equal to $13 \times 0.923 \approx 12.00$, and $12.00 / 24 = 0.500$). In contrast, summing the task-weighted transformed accuracy scores across those same four domains in Table 3 yields:
     $$\text{Sum of task scores} = (4 \times 0.771) + (2 \times 1.000) + (3 \times 0.889) + (3 \times 0.889) = 3.084 + 2.000 + 2.667 + 2.667 \approx \mathbf{10.417}$$
     Dividing by 12 submitted tasks and 24 total tasks gives a Conditional Transformed Accuracy of $10.417 / 12 = \mathbf{0.868}$ (rather than $0.923$) and a Penalized Transformed Accuracy of $10.417 / 24 = \mathbf{0.434}$ (rather than $0.500$). Moreover, even if a 13th task had been submitted in a separate run for Table 2 compared to the 12 submitted tasks in Table 3, increasing the cumulative task score from $10.417$ to $12.00$ would require that single additional task to achieve an accuracy score of $12.00 - 10.417 = 1.583$, exceeding the theoretical maximum of $1.000$. The authors should reconcile the task counts and accuracy values between Tables 2 and 3 or clarify how the ablation subset runs differed from the main evaluation.

2. **Discrepancy Between Evaluated Model Display Names and Reported API Snapshots (Abstract, Section 1, Section 4.2, Sections 5–7, and Tables 1–3):**

3. **Baseline Design and Omission of Stateful Parameter Persistence in the Symbolic Enumeration Baseline (Sections 4.2, 5.1.2, and 6.2):**
   In Section 5.1.2 (page 6), the authors note that the non-LLM Symbolic Enumeration baseline achieves only $0.750$ penalized transformed accuracy on elementary Class 0 (Atomic Unary) and Class 1 (Independent Unary) tasks, despite performing an exhaustive search over a bounded depth-1 space. The text attributes this sub-optimal performance to two factors: (i) greedy $L_1$ residual minimization getting trapped by collinear surrogate features in dense datasets, and (ii) *"the baseline lacks stateful parameter persistence for scalers ($\mu, \sigma$ and $\min, \max$), causing generalization loss on test holdouts."*
   This raises two potential concerns regarding baseline fairness, evaluation parity, and how Limitation 4 in Section 6.2 frames the baseline's scope:
   - **Stateful Scaler Persistence and In-Place Unary Matching:** Section 3.1 (page 3) explicitly defines `StandardScaler` and `MinMaxScaler` ($\Omega_3$) as deterministic operators whose empirical moments $(\mu, \sigma, x_{\min}, x_{\max})$ are fitted strictly on $\mathcal{D}_{\text{train\_before}}$ and applied as frozen scalar constants to $\mathcal{D}_{\text{test\_before}}$. Omitting parameter persistence from the symbolic baseline is an avoidable implementation artifact rather than an inherent algorithmic limitation of combinatorial search, as storing four scalar moments from $\mathcal{D}_{\text{train\_before}}$ during enumeration requires minimal implementation effort. Without it, the baseline is guaranteed to fail on out-of-sample test evaluation whenever a stateful scaler is selected. Similarly, because Class 0 and Class 1 tasks strictly modify columns in-place and preserve their original schema identifiers $c \in \mathcal{C}_{\text{before}}$ (Sections 3.1 and 3.2), a depth-1 unary search that checks whether column $c$ in $\mathcal{D}_{\text{after}}$ is a unary transformation of the *same* column $c$ in $\mathcal{D}_{\text{before}}$ before searching cross-column surrogates $c' \neq c$ would not be trapped by collinear features on elementary unary tasks.
   - **Absence of Established Symbolic and LLM-Guided Regression Baselines:** While the paper cites modern evolutionary, physics-inspired, and LLM-guided symbolic regression frameworks (such as PySR [6], AI Feynman [28], LLM-SR [24], and LLM-SRBench [25]) and attributes the baseline's weakness in Section 6.2 (Limitation 4, page 8) strictly to depth-3 combinatorial explosion, none of these established methods are included in the empirical evaluation. Because frameworks like PySR and LLM-SR combine structured search with continuous parameter optimization (`scipy.optimize` / BFGS), they directly address both the combinatorial explosion of brute-force search and the continuous threshold/parameter estimation bottleneck in Class 4 and 5 tasks. Fixing stateful parameter persistence in the combinatorial baseline, evaluating at least one established symbolic regression framework (e.g., column-wise PySR), and acknowledging the baseline's implementation constraints in Section 6.2 would provide a fairer and more rigorous cross-paradigm comparison.

4. **Asymmetric Multimodal Tool Access, Unreported Resource Utilization Metrics, Prompt Sensitivity, and Single-Seed Variance (Sections 4.1, 4.2, 5.1, and 6.2):**
   - **Confounded Multimodal Tool Access:** Section 4.2 (page 5) states that Claude 3.5 Sonnet and Gemini 3 Flash are given access to the `read_image(path)` tool alongside `run_python` and `submit_solution`, whereas GPT-5.4 Nano (`gpt-4o-mini-2024-07-18`) is restricted to `run_python` and `submit_solution`, even though `gpt-4o-mini` natively supports vision inputs. Withholding `read_image` from one vision-capable model while providing it to the other two introduces an unaddressed confounding variable in the cross-model comparison (and in Section 6.2, Limitation 3), and the ablation study (Section 4.3) does not isolate the effect of `read_image` versus text-only REPL execution.
   - **Missing Empirical Resource Consumption Breakdown and Prompt Confounding:** A central claim in Section 5.1.1 (page 6) is that Gemini 3 Flash suffers from an *"over-conservative stopping policy"* that exhausts its budget on $50.0\%$ of tasks, whereas Claude 3.5 Sonnet submits on $70.8\%$ and GPT-5.4 Nano submits on $100.0\%$. However, the Adaptive Tiered Budget Controller (Section 3.3.2) enforces three distinct termination limits simultaneously—tool calls ($T_{\text{calls}}$), cumulative tokens ($K_{\text{tokens}}$), and wall-clock time ($\Delta t_{\text{wall}}$)—while Gemini (`gemini-2.0-flash-exp`) is evaluated *"with thinking trace"* (which consumes output tokens) and invokes `read_image` (which Section 6.2 notes incurs non-trivial token consumption and latency). Because Section 5 never reports average tool calls, cumulative token consumption, `read_image` invocation counts, or which specific budget limit triggered termination per model, it is unclear whether Gemini's $50.0\%$ non-submission rate stems from deliberate REPL iteration, premature token-budget exhaustion from thinking traces and image ingestion, or sensitivity to system prompt phrasing (e.g., instructing the agent to submit its best candidate on tool call $T_{\text{calls}}(c) - 1$). Reporting these tracked resource metrics would directly substantiate the behavioral analysis.
   - **Single-Seed Evaluation Variance:** Each cell of the $8 \times 6$ full-factorial design consists of a single task instance generated with `seed = 42` ($N = 1$ per dataset-class pair in Table 3, $N = 8$ per complexity class in Table 1, and $N = 4$ per complexity class in the $N = 24$ ablation in Table 2), evaluated in a single greedy run ($T = 0.0$, `seed = 42`), where a single task outcome shifts class accuracy by $12.5\%$ and domain accuracy by $16.7\%$. Reporting variance across multiple task-generation seeds or trials (and noting this small per-stratum sample size in Section 6.2) would strengthen the statistical reliability of the comparisons.

### [Discussion, Limitations, Conclusion, and References] (Pages: 7-9)
#### Potential Mistakes and Improvements

1. **Unaddressed Threat to Validity: Exact Numerical Memorization and Target-Replacement Clues in Public Benchmark Datasets (Section 6.1)**
   - **Observation:** In Section 6.1 (*Threats to Validity and Data Leakage*), the discussion focuses primarily on how pre-training familiarity with public UCI and OpenML datasets (e.g., `diabetes`, `california_housing`) provides semantic schema priors over feature correlations that aid disambiguation, suggesting "semantically blinded tabular manifolds" as a future direction.
   - **Potential Concern:** Framing pre-training familiarity strictly around semantic domain knowledge of feature correlations understates a more direct form of potential contamination: **exact numerical row and summary-statistic memorization** of widely distributed public benchmark tables. Because the task construction (Section 4.1) applies precondition rejection sampling without modifying raw values and splits the dataset via a standard deterministic permutation (`seed = 42`), an agent with access to a Python REPL can potentially recognize exact numerical distributions, summary statistics (e.g., exact column means $\mu$, standard deviations $\sigma$, or extrema $x_{\min}, x_{\max}$), or specific outlier rows from canonical UCI/OpenML datasets. Furthermore, for Classes 3–5, Section 4.1 notes that newly synthesized interaction columns *"replace designated schema targets or adopt neutral indices."* When an interaction column overwrites an original schema column, an agent familiar with the canonical UCI/OpenML schema can immediately identify which column was replaced without inspecting numerical distributions, or even reconstruct the missing untransformed column from memorized row correlations. Expanding Section 6.1 to explicitly distinguish *semantic column-name priors* from *numerical distribution and schema memorization*—and suggesting affine input perturbations or synthetic copula resampling alongside full column-name anonymization—would strengthen the validity analysis.

2. **Noise-Free Deterministic Assumption (Section 6.2)**
   - **Observation:** Section 6.2 highlights four limitations (discrete operator vocabulary, stopping heuristics, vision tool overhead, and symbolic baseline scope), while all 48 benchmark tasks assume exact, noise-free deterministic mappings $\mathcal{D}_{\text{after}} = \mathcal{T}(\mathcal{D}_{\text{before}})$ evaluated under strict numerical tolerance ($\epsilon = 10^{-4}$).
   - **Potential Concern:** Real-world observational pipelines often involve stochastic measurement noise, floating-point truncation, or missing data imputation, where agents relying on near-zero residual stopping thresholds ($\lVert \widehat{\mathcal{D}} - \mathcal{D} \rVert_\infty < 10^{-6}$, discussed in Section 5.1.1) would struggle to converge. Explicitly noting this noise-free deterministic assumption in Section 6.2 would provide a more complete account of the benchmark's operational boundaries.

3. **Claim Alignment and Synthesis of the Ablation Study in the Conclusion (Section 7)**
   - **Observation:** Section 7 (*Conclusion*) states: *"By formalizing six structural complexity classes across eight authentic real-world domains and enforcing strict epistemic sandbox isolation, we provide the first rigorous benchmark disentangling hypothesis discovery from code synthesis across 48 standardized tasks ($N = 48$)."* At the same time, Section 7 omits the actual quantitative findings of the ablation study, while Section 5.2.2 (top of Page 7) concludes that under the *Oracle Operators Revealed* condition, *"When the latent mathematical operations are disclosed, programmatic code compilation achieves near-perfect fidelity in frontier LLMs."*
   - **Potential Concern:** There are two alignment issues in how this conclusion is synthesized across Sections 5.2.2 and 7:
     1. *Scope of the Ablation Study:* The three-mode ablation study that disentangles discovery from synthesis was conducted on a stratified subset of $N = 24$ tasks using a single model (Gemini 3 Flash), rather than across all $N = 48$ tasks and all evaluated models as implied by the summary sentence in Section 7.
     2. *Conditional vs. Unconditional Synthesis Fidelity:* As described in Section 4.3(3), revealing the multiset of ground-truth operator names $\mathcal{O}^*$ does not reduce the task to pure code compilation: the agent must still search over column-to-operator assignments, DAG topological ordering, and continuous threshold/scaler parameters, which is why the agent still failed to submit on $8$ of $24$ tasks ($33.3\%$ non-submission rate, yielding $0.667$ penalized accuracy in Table 2). Thus, programmatic compilation achieves $100\%$ fidelity only *conditionally* on the $16$ submitted tasks where column mapping and parameter optimization converged before budget exhaustion. Explicitly incorporating the ablation findings into Section 7—while qualifying both the $N = 24$ subset scope and the distinction between *operator vocabulary identification* and *column/parameter search*—would better align the conclusion with the empirical evidence.
